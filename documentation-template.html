Writing your report

Documentation Template

The official structure and formatting rules for your FYP-I proposal and FYP-II report. Two formats are available — a Word (DOCX) template, and a LaTeX template pack split by phase and project track. Use whichever your supervisor prefers, from your first draft, not just the final one.

Required structure

Chapters your report must include

#ChapterWhat it covers
1IntroductionProblem statement, motivation, objectives, scope
2Literature ReviewRelated work and how your project differs
3Requirements & AnalysisFunctional/non-functional requirements, use cases
4System DesignArchitecture, ER/class diagrams, technology stack
5ImplementationKey modules, algorithms, notable engineering decisions
6Testing & EvaluationTest cases, results, performance where relevant
7Conclusion & Future WorkOutcomes against objectives, limitations, next steps
—References & AppendicesCitations, user manual, extra diagrams/code listings

This structure applies to the DOCX template above. If you use the LaTeX pack below instead, each template already builds this structure in for you — chapter-by-chapter for FYP-II, section-by-section for FYP-I.

Formatting

Page setup

A4 size, 1-inch margins, 1.5 line spacing, 12pt body text in Times New Roman, page numbers bottom-center.

Length

Target length

50–90 pages excluding appendices, scaled to project complexity — quality over padding.

Citations

Reference style

IEEE citation style throughout, with a consistently numbered reference list.

Originality

Similarity check

Must be under the 19% similarity threshold defined in the Guidelines page before submission is accepted.

Alternative format

LaTeX Template Pack

Four ready-to-use LaTeX templates covering both phases (FYP-I proposal, FYP-II report) and both project tracks (Research-based, Application-based). All four share the same University of Lahore, Sargodha Campus branding, colour palette, and fonts, so your proposal and final report look like a consistent, professional pair.

TemplateUse forFormat
FYP-I Research-Based ProposalFYP-I proposal, if your project investigates a research questionSingle document, ~12 pages
FYP-I Application-Based ProposalFYP-I proposal, if your project builds a software system/productSingle document, ~13 pages
FYP-II Research-Based ReportFYP-II final report, research trackMulti-chapter, ~29 pages
FYP-II Application-Based ReportFYP-II final report, application/development trackMulti-chapter, ~32 pages

Unsure which track fits? If your project investigates a hypothesis, compares algorithms/methods, or evaluates results against a baseline with metrics, it's research-based. If it designs and builds a working web, mobile, or desktop application for real or realistic users — validated mainly through testing — it's application-based. Ask your supervisor early: this decision determines both your FYP-I and FYP-II template, and most groups stay on the same track for both semesters.

Working with LaTeX

Getting started with the template pack

Setup

Overleaf (recommended)

Create a free account at overleaf.com, then New Project → Upload Project with the template's .zip file. Overleaf detects the bibliography step automatically on first compile — no local install needed.

Setup

Local install

Install TeX Live or MiKTeX, unzip the template folder, then compile from a terminal in that folder. Recompile every time you make changes to check your work.

Filling it in

Placeholders & instructions

Every spot to edit is marked in green bold text in square brackets. Grey shaded boxes explain what belongs in that section — delete each box once you've written the section it describes.

Citations

references.bib

Add one BibTeX entry per source to references.bib, then cite it in text with \citep{key} or \citet{key}. LaTeX numbers and orders the reference list automatically.

Before submitting: no placeholder text or instruction boxes remain, every figure/table is referenced in the text, every references.bib entry is actually cited, the similarity check is complete and filled in on the Declaration page, and the document compiles cleanly from a fresh copy. Full troubleshooting and the complete checklist are in the Student's Guide above.
